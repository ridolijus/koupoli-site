# Technical SEO audit brief and issue handoff

Use this template to agree the scope before an audit. It is a working document, not a completed client audit or a promise of search results.

- Access available: Search Console, analytics, crawl exports and server logs, where applicable:
- Person approving changes and developer responsible for implementation:
- Deliverables, completion date and any separately priced implementation or retesting:
- Out-of-scope work:

## Record an issue

**Issue:**

**Affected URLs and template:**

**Observed behavior:** State what the request or rendered page actually shows. Include the test date, environment and relevant response, screenshot or export.

**Business relevance:** Explain which important pages or user paths are affected. Separate confirmed behavior from an untested indexing hypothesis.

**Expected behavior:** Describe what should change, without assuming an implementation technique before checking the platform.

**Suggested fix and dependencies:**

**Priority and effort:** Explain the reason for the priority. A crawler severity label alone is not a business case.

**Implementation owner and approval:**

**Acceptance test:** Give repeatable steps, the expected result and the representative URLs to retest. Check the deployed page, not only a staging screenshot.

**Follow-up:** Record the release date and any Search Console checks separately. A passing technical test does not guarantee indexing or a ranking gain.

## Close the audit

Deliver the prioritized findings, supporting evidence, limitations, implementation responsibilities and agreed verification steps. Keep a record of unresolved dependencies and accepted risks.
